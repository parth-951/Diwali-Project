## Method

`generate_reference.py` creates inputs with a fixed seed (20261103), computes the answers with NumPy and writes both to a file. `verify_numerical.cpp` runs the same operations through MiniTensor and compares.

A result passes when its shape matches exactly and the largest element-wise difference is at most `1e-10 * max(1, largest |expected|)`. This limit was set before the first run. Exact equality isn't required, because NumPy's BLAS adds terms in a different order. An incompatible case passes when NumPy raises an error and MiniTensor throws `std::invalid_argument`.

### Known differences from NumPy

MiniTensor's `matmul` and `transpose` are defined for 2-D tensors only. NumPy also accepts other ranks. MiniTensor rejects them with an exception instead of returning a different answer, and the "Rejected by design" row confirms this.

## CUDA benchmarks

These numbers measure the optional CUDA backend (`-DMINITENSOR_USE_CUDA=ON`, double precision). `matmul` calls cuBLAS `dgemm`. The other operations are MiniTensor's own kernels. The CPU tables above are not affected by this backend.

### How it was measured

- **Warm-up:** 3 runs per workload are discarded. They also cover the one-time CUDA and cuBLAS setup.
- **Synchronization:** `cudaDeviceSynchronize()` runs before the clock starts and again before it stops, because a GPU call returns before the work has finished.
- **Repeats:** 15 timed runs per workload. The same seeded input data as the CPU benchmark is used.
- **sum:** it has to return its answer to the host, so its GPU time includes small copies back and forth, and it has no separate launch time.

### Timings

Times are in milliseconds, and lower is better.

- **GPU median:** inputs already on the GPU, clock stopped after synchronizing. This is the real GPU time.
- **Launch only:** the same call with the clock stopped before synchronizing. This is what a benchmark without synchronization would wrongly report.
- **End to end:** host tensors in and out, including both copies. This is what a caller with host data pays.

### Run it yourself

```bash
sudo apt-get install -y cmake g++ python3-numpy
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
python3 verification/run_verification.py --bin-dir build
```

To include the GPU results, install the CUDA Toolkit and add `-DMINITENSOR_USE_CUDA=ON` to the first `cmake` command.
